# Advanced plugin capability boundaries

This page describes observable interfaces and known limits. Earlier claims of universal production readiness, automatic middleware, and percentage improvements were not supported by package evidence.

| Capability | Contract |
| --- | --- |
| Zod validation | Generates schema/helper output; install Zod 4 and call helpers explicitly |
| Branded types | Schema-backed Zod guards/assertions/create helpers and nominal/auth metadata; auth metadata does not authorize server actions |
| Request deduplication | Manual helper calls, canonical request identity, explicit session scope, custom runtime key callback |
| Cache expiry/stale policy | Applies to helper calls and endpoint policies; not automatic client middleware |
| Cache invalidation/statistics | String/regex URL invalidation and measured counters |
| Performance timing | Optional generated wrappers/helpers; instrument calls explicitly |
| Performance reports | `generateReports` writes a format-selected performance-report artifact; public report utility also returns a string |
| Bundle/dependency analysis | Generated-source byte counts and estimates; not a real bundled artifact |
| Memory observation | Generator-process observation; not continuous client/browser monitoring |
| Regression thresholds | Current observed durations; no guaranteed historical baseline comparison |

The `strict-mode` plugin is retired: active use fails with a diagnostic to use core strict defaults. React hooks are generated by `generateHooks`/`--hooks`. `generateQueries` and a TanStack adapter are unavailable.

Some historical plugin options remain experimental or unsupported: `optimizeBundle` does not establish bundle optimization, description metadata does not customize Zod error messages, and enabling monitoring does not instrument every endpoint automatically. Do not claim bounded generation memoization based on a separate runtime cache. Configuration or option combinations that lack an observable supported behavior should produce a diagnostic, or be omitted from application configuration.

Supported helper factories and utilities are exported from the package root. Generated runtime classes live in generated output. Use [plugin integration](PLUGINS.md), [development](PLUGIN_DEVELOPMENT.md), and [advanced design contracts](ADVANCED_PLUGIN_DEVELOPMENT.md); do not use undocumented deep imports.

Evidence needed for broader claims includes compiled consumer modules, runtime validator inputs, actual request identity/expiry assertions, and measurements of real bundled applications. A generator build, output string check, or unexecuted CI configuration does not establish those claims.
