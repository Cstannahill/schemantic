# Plugin development

A plugin implements `SchemanticPlugin`. Import public types from the package root. Hooks can return promises except the synchronous schema transform and custom generator functions.

```ts
import type { SchemanticPlugin } from 'schemantic';

export const plugin: SchemanticPlugin = {
  name: 'example',
  version: '1.0.0',
  description: 'Adds generation diagnostics',
  beforeGeneration(context) {
    console.log(`Generating ${context.schema.info.title}`);
  },
  afterTypeGeneration(_name, generatedType) {
    generatedType.content = '/** Generated by example */\n' + generatedType.content;
  },
};
```

Supported hooks and signatures:

| Hook | Arguments |
| --- | --- |
| `beforeGeneration` | `context` |
| `afterGeneration` | `context, result` |
| `beforeTypeGeneration` | `typeName, resolvedSchema, context` |
| `afterTypeGeneration` | `typeName, generatedType, context` |
| `beforeClientGeneration` | `context` |
| `afterClientGeneration` | `generatedClient, context` |
| `transformSchema` | `resolvedSchema, context`; returns a resolved schema synchronously |
| `customTypeGenerators` | Record of functions `(resolvedSchema, context) => GeneratedType` |
| `customClientGenerators` | Record of functions `(context) => GeneratedApiClient` |

There are no `beforeSchemaLoad`, `afterSchemaLoad`, `beforeFileWrite`, `afterFileWrite`, CLI command extension, or automatic runtime middleware hooks in this interface. Register only implemented hooks. Custom outputs must accurately list `exports` and `dependencies` and preserve required imports. Avoid modifying source data retained by your caller.

Programmatic registration:

```ts
import { Schemantic } from 'schemantic';
import { plugin } from './plugin.js';

const generator = new Schemantic({ schemaFile: './openapi.json', outputDir: './generated' });
const manager = generator.getPluginManager();
manager.registerPlugin(plugin);
manager.enablePlugin(plugin.name);
const result = await generator.generate();
if (!result.success) throw new Error(result.errors.map(error => error.message).join('\n'));
```

CLI loading requires a compiled JavaScript module (`.cjs`, `.mjs`, or `.js`). Export the plugin directly, as default, or as `plugin`; use the filename/package specifier in config or `generate --plugins`. The loader resolves packages from the consumer, not the generator's internal dependencies. Duplicate exported names fail. `plugin load` is inspection only.

Test plugins using actual consuming code and runtime assertions. String output alone does not establish that a module compiles, a validator rejects invalid data, or a helper preserves request identity. Cover disabled options and combinations with other plugins. Hook failures must appear as generation failures; do not treat a logged warning as successful required plugin execution.
